# Arkfire Design Archive Decision Reconciliation

**Date:** 2026-07-28  
**Source decision register:** `docs/governance/ARKFIRE_DECISION_REGISTER.md`  
**Purpose:** Reconcile the completed Codex Observer, UHTO, Legacy, Current Vision, and design-concept audits without rewriting the source archive.

## Ratification rule

The source Decision Register remains immutable archive evidence. This addendum records the operational interpretation applied to the active Arkfire Glyph & Tone Studio work. Items marked **Recommend Lock** still require deliberate governance ratification before the original register is changed.

## Provisional decisions whose review triggers are complete

### DR-009 — Codex Role

**Source state:** Provisional  
**Review trigger:** Codex Observer and UHTO audits  
**Trigger status:** Complete  
**Recommendation:** **Lock**

Codex should remain an optional integrated view over Library, Lore, Continuity, entities, artifacts, timelines, perspectives, and Resonance Network relationships. It is not the sole persistence authority.

**Applied now:** Tone profile and journey definitions are first-class artifacts; Notion and Supabase are views/adapters rather than an exclusive Codex authority.

### DR-010 — Heartbeat Role

**Source state:** Provisional  
**Review trigger:** Codex Observer and UHTO audits  
**Trigger status:** Complete  
**Recommendation:** **Lock**

The heartbeat is an opportunity service that decides whether evaluation is warranted. It does not force narrative, continuity, bridge formation, or positive metric growth.

The historical one-minute d256 exact-face-6 behaviour remains an importable profile, not the universal default.

### DR-011 — Framework Connection Model

**Source state:** Provisional  
**Review trigger:** external-interface and Observer evidence  
**Trigger status:** Complete enough for boundary lock  
**Recommendation:** **Lock boundary, keep transport details open**

Framework connections require declared capabilities, explicit permission, schema version, provenance, identity/ontology mapping, conflict policy, and reviewed writeback. Connection does not grant authority.

The exact transport, package handshake, and initial connection modes remain implementation decisions.

## Open decisions with stronger recommendations

### DR-012 — Lore Seed Mutability

**Recommendation:** Original seed plus project override layers.

This preserves Legacy ontology provenance while allowing Typical and Custom project modes. Do not mutate the historical seed in place.

### DR-013 — Essence, Cognition, and Activation Categories

**Recommendation:** Keep as optional framework-profile categories until ontology review proves they belong in neutral core.

### DR-014 — AEF Naming and Scope

**Recommendation:** Preserve AEF as a Legacy import alias, not the new universal exchange-format name.

The audits found multiple incompatible observation shapes. Current Arkfire should use purpose-specific versioned contracts inside a common envelope.

### DR-015 — Background Runtime

**State remains:** Open.

The product behaviour is locked: elapsed time and protected checkpoints must reconcile after interruption. The implementation may be reopen reconciliation, a local service, OS scheduling, hosted runtime, or hybrid.

### DR-016 — Heartbeat Default

**Recommendation:** Guided setup or disabled by default. Historical and canon-aware profiles remain opt-in.

### DR-017 — Continuity Directory and File Structure

**State remains:** Open.

JSON/JSONL authority is locked, but exact directory, branch, rejected-proposal, migration, and cache layout should be designed from the first complete persistence slice.

### DR-018 — Continuity, Library, Lore, and Codex Boundaries

**Recommendation:** **Lock the working distinctions.**

- Library owns source material and source-derived knowledge.
- Lore owns symbolic ontology and correspondence.
- Continuity owns accepted project/world state.
- Journal owns observer reflection.
- Codex is an integrated view.
- Artifact Store owns generated/imported artifact identity and lineage.

Entity definitions and accepted memories remain shared through explicit authority references rather than duplicated ownership.

### DR-019 — Journal Promotion

**State remains:** Open.

Promotion must remain explicit, attributable, impact-assessed, and reversible where possible.

### DR-020 — Glyph Derivation Policy

**State remains:** Open.

The archive establishes requirements for reproducibility, inspectability, lineage, and visible stochastic behaviour, but not the final grammar.

### DR-021 — Framework Connection Permissions

**Recommendation:** Initial release supports **read-only** and **proposal-only**. Bidirectional reviewed writeback follows only after acceptance tests.

### DR-022 — Canon-to-Framework Convergence Threshold

**State remains:** Open.

No automatic merge is permitted. Comparison, risk assessment, preserved parents, and reviewed branch creation are mandatory.

## New operational decisions applied to Glyph & Tone Studio

### DA-001 — Parent product and subsystem placement

Arkfire Dimensional World Bridge is the complete product. World Reception is a Hearthgate surface owned by Glyph & Tone Studio.

### DA-002 — Tone triad

A complete paired-world tone operation contains:

1. World One tone
2. World Two tone
3. Mathematically derived Bridge Tone

The Bridge Tone is not merely simultaneous playback or unexamined averaging.

### DA-003 — Tone artifacts and receipts

Profile definitions, journeys, renders, collision reports, generation results, and auditions are first-class artifacts or artifact-linked records with version, provenance, perspective, and lineage.

### DA-004 — UI inheritance

The concept image is a layout contract, not a pixel-perfect production design. Preserve:

- static product/module header
- world-clock strip
- large main workspace
- adaptive Context Inspector
- user settings
- guarded Developer Mode
- configurable CRM-style surfaces

### DA-005 — Authority shelves

Signal arithmetic, measured/retrieved evidence, active research, interpretation, subjective intention, symbolic canon, and generated possibility remain separately labelled.

### DA-006 — Framework-specific metaphysical rules

Bridge permanence, Convergent Pressure, Reunion Events, post-embodiment routing, latent anchors, and similar checkpoint rules are not default universal core truth.

They may be enabled as fictional, mythic, or project-defined framework policies with explicit provenance and scope.

### DA-007 — Completion truth

Static schema success cannot conceal unsupported runtime features. A declared modulation, transition, route, or export must be rendered, visibly rejected, or marked blocked.
